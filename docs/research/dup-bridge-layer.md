## Details

- #1 is the biggest win. All 8 sites sit inside `_dispatcher.InvokeAsync(() => { var dte = SessionDte(...); try { ... } catch... })`. A single wrapper also absorbs #2 if it passes `Debugger` (not `DTE`) to the lambda: `RunOnDebugger<T>(sessionId, Func<Debugger,T> f)`. Note `RunSnapshotAsync` (1386-1416) already does exactly this for the read path — `Pause`/`ResumeCore`/`StepCore`/`AttachProcess`/`Launch` predate it and still spell the try/catch by hand. Cheapest fix: route those five through `RunSnapshotAsync`-style wrapper with a non-default budget (they need `IssueBudgetMs`), rather than a second helper.
- #3 strings compared byte-equal except session-id interpolation: `SessionDte` (146-148), `SessionComError` (180-181), `SessionInvalidCom` (199-200) all build `("vs-not-running", $"the VS instance bound to session {sessionId} is gone", "call attach again")`. The set-BP `gone` branch (521-524) duplicates the same two outcomes under `lock (_gate)`.
- #5: `RequireModeAsync` extraction already happened; only the 4-line `catch (ModeReadTimeoutException)` echo remains ×3.
- #8 specifics: `TrySnapshotAsync` 1558-1562 (`DebugDomainException`) and 1563-1567 (`TimeoutException or OperationCanceledException`) have identical bodies (`TraceFallback(...); return (null, null);`). Same for `StillExists` 691-698.
- Fake-vs-live (#9–#13): `ProcessLaunch.AlreadyBound`, `BreakpointOptions.ForeignId/ForeignWarning/NotFound/Exists`, `ExceptionConfig.*`, `ModuleListing.*`, `RunToCursor.RunAsync` are already shared — the items above are the remaining unshared guards. `ListSessionsAsync` live (234-237) vs fake (143-144) differ only by the ` [fake]` suffix; not worth a helper.
- `IDebugBridge.cs` (1-31): pure interface, no duplication. `ComDispatcher.cs`: `Register`/`Revoke` try/catch best-effort comments repeat the same sentence but are 1-liners on distinct interop calls — not worth merging. `ComErrorMapper.cs`: `IsDisconnected`/`IsCallRejected`/`IsRefusal` + `ToDomain` switch are already the shared mapping; `DteDebugBridge` uses them consistently except `ReadExceptionMessage` (1374, `when (!IsDisconnected)`) and `SetExceptionSetting` (1300, same) which inline the negation — fine as-is.
