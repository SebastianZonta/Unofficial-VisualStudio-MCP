# Architecture — Unofficial-VisualStudio-MCP run-1 (deep, full scope)

Product: local MCP stdio server driving Visual Studio 2026 via EnvDTE COM. 21 tools: attach/list/detach, attach_process/launch_process, breakpoints, step/pause/resume/run_to_cursor, exception settings, read_stack/read_variables/evaluate/set_variable. Users: MCP client operator (AI agent) + human developer owner on same Windows box, same user/elevation. Trust-sensitive actions: attach to PID, launch .NET exe, write variable, set exception mode, move execution.

Comparable baseline: MCP stdio servers (ModelContextProtocol 2.2.0) + VS COM automation via ROT/DTE. Same trade-off as other local debug bridges: stdio peer is fully trusted once spawned; isolation relies on OS user boundary, not protocol auth. No comparable shared here dismisses a finding; ROT-spoof and same-user-debug patterns are known in this class and strengthen relevant leads.

Offline build/test via dotnet slnx; live/E2E needs Windows+VS2026 (unavailable here — Linux host).
